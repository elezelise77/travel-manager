# 여행 상황판 (Trip Board)

친구들과 떠나는 여행의 **비용 정산 · 일정 · 숙소 · 사진**을 한 링크에서 관리합니다.
서버 없이 **구글시트 한 장**으로 돌아갑니다.

- 자료는 전부 **사용자 본인 구글 계정**(구글시트 + 구글드라이브)에 저장됩니다
- 친구들은 **아무것도 설치하지 않습니다** — 링크만 받으면 됩니다
- 서버비 0원

---

## 무엇으로 만들었나

| 역할 | 사용 |
|---|---|
| 자료 저장 | 구글시트 |
| 화면 · 계산 | Google Apps Script (시트에 바인딩된 컨테이너 스크립트) |
| 사진 저장 | 구글 드라이브 |
| 방장용 도우미 앱 | Electron (Windows EXE) |

의존성은 데스크톱 앱의 Electron 뿐입니다. 웹앱 쪽은 라이브러리 없이 순수 HTML/CSS/JS 입니다.

## 화면 자동 업데이트

화면(`Index.html`)을 시트에 붙박아 두지 않고, 깃허브 Pages 에서 받아와 그립니다.
그래서 화면을 고치면 쓰는 사람들이 붙여넣지 않아도 반영됩니다.

```
doGet
 ├ 보관해 둔 화면이 있으면 그것 (6시간)
 ├ 없으면 UPDATE_URL 에서 받아옴 → 검사 후 보관
 └ 못 받아오면 시트에 붙여넣어 둔 Index.html   ← 주소가 죽어도 앱은 안 멈춥니다
```

- `Code.gs` 의 `UPDATE_URL` 에 Pages 기본 주소를 넣으면 켜집니다 (비우면 꺼짐)
- 쓰는 사람은 설정 탭에서 끌 수 있습니다
- 받아온 HTML 이 이 앱의 화면인지(길이·표식) 확인한 뒤에만 씁니다
- 켜는 법: `자동업데이트-켜는법.txt`

**서버 로직(`Code.gs`)은 자동화하지 않았습니다.** 구매자 시트를 직접 읽고 쓰는 코드를
원격에서 받아 실행하면, 서버가 뚫렸을 때 구매자 자료가 위험합니다.
대신 EXE 가 `APP_VERSION` 을 비교해 붙여넣는 법을 안내합니다.

화면만 고쳤다면 `Index.html` 의 화면 버전만 올리고 `APP_VERSION` 은 그대로 두세요.
그래야 EXE 가 불필요한 업데이트 안내를 띄우지 않습니다.

## 화면에서 바로 쓸 수 있는 범용 창구

`google.script.run` 은 `Code.gs` 에 적힌 함수만 부를 수 있어서, 기능을 추가할 때마다
서버 코드를 고쳐야 했습니다. `api` 창구를 열어두어 그 빈도를 줄였습니다.

```js
google.script.run.api(TOKEN, 'ensure', ['준비물', ['항목','담당','비고']])
google.script.run.api(TOKEN, 'put',    ['준비물', 0, {항목:'텐트', 담당:'동현'}])
google.script.run.api(TOKEN, 'list',   ['준비물'])
google.script.run.api(TOKEN, 'del',    ['준비물', 5])
```

- 기본 시트(참석자명단·지출대장 등)는 이 창구로 **구조를 바꿀 수 없습니다**
- `비밀번호`·`권한` 열은 읽기·쓰기 모두 차단됩니다
- `등록자` 열이 있는 시트는 등록한 본인과 관리자만 고칠 수 있습니다

## 설치 (웹앱)

자세한 그림 안내는 `SETUP-GUIDE.html` 을 브라우저로 여세요. 요약하면 이렇습니다.

1. `sheets.new` 로 **빈 스프레드시트**를 하나 만듭니다 (남의 시트를 복사하지 않습니다)
2. `확장 프로그램` → `Apps Script`
3. `Code.gs` 붙여넣기, HTML 파일 `Index` 만들어 `Index.html` 붙여넣기
4. 함수 `초기설정` 실행 → 권한 승인
5. `배포` → `새 배포` → **웹 앱** / 실행: 나 / 액세스: **모든 사용자**
6. 나온 `.../exec` 주소로 접속 → 첫 로그인한 사람이 관리자

데스크톱 앱을 쓰면 2~3번의 코드를 **버튼 한 번으로 클립보드에 복사**해 줍니다.

코드를 고친 뒤에는 `배포` → `배포 관리` → 버전 **새 버전** → `배포` 를 해야 반영됩니다.

## 빌드 (데스크톱 앱)

```bash
cd desktop-app
npm install
npm run dist
```

`desktop-app/dist` 에 설치본과 포터블 EXE 가 생깁니다.

웹앱 코드를 고쳤다면 빌드 **전에** 최신본을 앱 안에 넣어 주세요.
앱은 여기 있는 파일을 클립보드로 복사해 주고, 이 파일의 `APP_VERSION` 으로 업데이트 여부를 판단합니다.

```bash
copy ..\google-apps-script\Code.gs     code\Code.gs
copy ..\google-apps-script\Index.html  code\Index.html
```

## 정산이 어떻게 계산되나

**참석자** N분의 1을 기본으로 하되, **실제로 오간 돈을 한 건씩 기록**합니다.

```
잔액 = (내가 결제한 돈) − (내 부담금) + (내가 보낸 돈) − (내가 받은 돈)
```

- 잔액이 음수면 더 보낼 돈, 양수면 돌려받을 돈
- 잔액 기준으로 **최소 송금 횟수**를 다시 계산합니다
- 지출이 나중에 추가·수정돼도 전부 자동으로 다시 계산됩니다
- 여행 전에 미리 보낸 돈(**선납**), 나눠 보낸 돈(**부분 납부**), 지출이 줄어 돌려주는 돈(**환급**)이
  모두 같은 구조로 처리됩니다

### 나눌 사람을 정하는 규칙

1. 참석여부가 **불참**인 사람은 언제나 빠집니다
2. **미정**·무응답은 설정 `정산 인원` 에서 [포함 / 제외] 선택 (기본 포함)
3. 지출 항목에 **참여자**를 골라두면 그 사람들끼리만 나눕니다 (비워두면 위 1·2 대상 전원)

나누어떨어지지 않는 금액은 1원 단위까지 배분해서 **부담금 합계 = 총지출**, **잔액 합계 = 0** 이 항상 성립합니다.
인원이 바뀌어도 이미 보낸 돈은 건드리지 않으므로, 부족분·환급이 저절로 다시 잡힙니다.

관리자는 **수시정산 / 여행후일괄** 중에서 운영 방식을 고를 수 있고, 지출을 조기 **마감**할 수 있습니다.

## 권한

| | 관리자 | 일반 |
|---|---|---|
| 일정 · 식사 · 이동 · 숙소 · 인원 · 여행정보 | ○ | ✕ |
| 지출 등록 | 전부 | 본인 결제 건만 |
| 지출 수정 · 삭제 | 전부 | **등록한 본인만** |
| 송금 기록 | 전부 | 본인이 보낸 것 |
| 참석여부 | 전원 대신 가능 | 본인 |
| 건의사항 · 사진 | 전부 삭제 가능 | 본인 글 |

비밀번호는 **SHA-256 해시**로 저장하며 평문은 어디에도 남지 않습니다.
로그인 토큰은 ScriptProperties 에 14일 보관합니다.

- 한 시트 = 한 여행. 다음 여행은 설정의 `다음 여행 준비` 로 비우고 이어서 씁니다
